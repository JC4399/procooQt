# The agent harness, explained simply — 代理人駕馭，簡單說明

You have probably already talked to a language model. It can answer questions all day, but the moment you ask it to actually go do something, it stalls. This guide closes that gap: why the model can do real work for you at all, how to set it up so it does the job well, and why the whole setup improves or slowly degrades over time. No technical background is needed. To see why the model can do any of this, start with how it is built.

你大概已經和語言模型說過話了。它能整天回答問題，但你一請它真的去做點什麼，它就卡住。這份指南補上這個落差：模型為什麼能為你做真正的工作、該怎麼設定讓它把工作做好、以及整個設定為什麼會隨時間改善或慢慢退化。不需要任何技術背景。想明白模型為什麼能做到這些，要從它是怎麼打造的說起。

## 1. Why a language model can work for you — 為什麼語言模型能為你工作

### 1.1 How a language model is trained — 語言模型是怎麼訓練的

A language model is a program trained on an enormous amount of text: web pages, books, articles, code, papers, conversations. The training method is simple to describe even though the scale is huge. The model is shown a piece of text and asked to predict the next word. Each wrong guess nudges its internal numbers a little. Repeat that trillions of times over trillions of words and the model absorbs facts and the patterns behind them: how a question is normally answered, how an explanation is structured, how a plan is written out, how a mistake gets corrected.

語言模型是一個在海量文字上訓練出來的程式：網頁、書籍、文章、程式碼、論文、對話。儘管規模龐大，訓練方法說起來很簡單。給模型看一段文字，要它預測下一個字。每次猜錯，它內部的數字就被輕輕推一下。在數以兆計的字詞上重複數以兆計次，模型就吸收了事實以及背後的圖樣：問題通常怎麼回答、解釋怎麼組織、計畫怎麼寫出來、錯誤怎麼被修正。

Technically the model is a neural network of the transformer family, with billions to trillions of parameters, trained on next-word prediction over that corpus. You do not need the jargon. The useful picture is this: after this first stage, called *pre-training*, the model is like someone who has read an entire library. That person can quote half the library but has never done a single thing. Knowing a lot and being a good assistant are two different things, and straight out of pre-training the model mostly just continues whatever text you start. It completes patterns; it does not yet reliably do what you ask. Closing that gap is the job of the next stage.

技術上來說，模型是一個 transformer 家族的神經網路，有數十億到數兆個參數，在那份語料上以預測下一個字來訓練。你不需要懂這些術語。有用的圖像是：經過這第一個階段——稱為「預訓練」——之後，模型就像一個讀完整座圖書館的人。那個人能背出半座圖書館，卻一件事也沒做過。知道很多和是個好助手是兩回事，剛出預訓練的模型多半只會把你開頭的文字接續下去。它完成圖樣；它還不能可靠地照你說的做。彌補這個落差是下一個階段的工作。

### 1.2 Post-training: teaching the raw model to be an assistant — 後訓練：把生模型教成助手

The second stage is called *post-training*, and it is where a raw text completer becomes a helpful assistant. Think of it as sending that well-read person to assistant school. It has several parts, and each part teaches something different.

第二個階段稱為「後訓練」，一個只會補全文本的生模型在這裡變成有用的助手。把它想像成送那個博學的人去上助手學校。它分為幾個部分，每個部分教的東西不同。

First, *instruction tuning* (also called supervised fine-tuning). The model is shown many example conversations: a request, then a good response. The examples are written by people, or generated by a stronger model. They often include multi-turn dialogue so the model learns how conversations flow across turns. Practicing these examples teaches the model to follow instructions, format its answers usefully, and adopt a helpful tone.

第一是「指令微調」（也叫監督式微調）。給模型看大量對話範例：一個請求，接著一個好的回應。這些範例由人撰寫，或由更強的模型生成。它們常包含多輪對話，讓模型學會對話如何在輪次之間流動。練習這些範例，教會模型遵循指令、把答案排成有用的形式、並採取有幫助的語氣。

The training data is a large collection of prompt-response pairs: a request on one side, a good answer on the other. "Write a poem about autumn" paired with an actual poem, "explain recursion to a ten-year-old" paired with an actual explanation. The pairs come from two sources. Human-written examples are the highest quality but expensive to produce at scale. Synthetic examples are generated by a stronger model and then filtered for quality, which scales much more cheaply. Diversity matters as much as volume: the collection should cover a wide range of tasks (summarizing, coding, brainstorming, refusing harmful requests), output formats (lists, tables, JSON, plain prose), and tones.

訓練資料是大量提示—回應配對：一頭是請求，另一頭是好答案。「寫一首關於秋天的詩」配上一首真正的詩，「向一個十歲小孩解釋遞迴」配上一段真正的解釋。配對來自兩個來源。人工撰寫的範例品質最高，但大量生產很貴。合成範例由更強的模型生成再過濾品質，擴充起來便宜得多。多樣性和數量一樣重要：這份集合應該涵蓋各種任務（摘要、寫程式、腦力激盪、拒絕有害請求）、各種輸出格式（清單、表格、JSON、純散文）和各種語氣。

The training itself reuses the same objective as pre-training, next-word prediction, with one important difference: the loss is computed only on the response tokens. The prompt part is masked out, so the model is scored only on producing the good answer that follows the question, not on reproducing the question itself. Formally, the model maximizes the likelihood of the response given the prompt, summed over the response tokens. Because the format is identical to pre-training, the model absorbs the new behavior smoothly without unlearning what it already knows. In practice only a few passes over the data are used, with a small learning rate, to avoid overfitting to the exact wording of the examples.

訓練本身沿用與預訓練相同的目標——預測下一個字——但有一個重要差異：損失只在回應的詞元上計算。提示的部分被遮蔽起來，所以模型只因「給出跟在問題後面的好答案」而被評分，而不是因重現問題本身。形式上，模型最大化「給定提示下回應」的概似，在回應的詞元上加總。由於格式與預訓練完全相同，模型能平順地吸收新行為，而不會忘掉它已經會的東西。實務上只在資料上跑少少幾趟，用很小的學習率，以免對範例的確切措辭過度擬合。

Multi-turn conversations are included on purpose. A single pair teaches one exchange; a full conversation teaches turn-taking, referring back to earlier context, correcting oneself, and asking a clarifying question when the request is ambiguous. To train on these, every message is tagged with a role, system, user, or assistant, and the whole conversation is wrapped in a chat template: special tokens that mark where each message begins and ends. The model learns to generate those markers correctly, which is why a chat model holds a coherent multi-turn conversation instead of treating every message as a fresh text completion.

多輪對話是刻意納入的。一組配對教的是一次交換；一整場對話教的是輪流發言、回頭參照先前的上下文、自我更正、以及在請求模糊時提出澄清問題。為了用它們訓練，每則訊息都標上一個角色——系統、使用者或助手——而整場對話被包在一個對話模板裡：標示每則訊息起訖的特殊詞元。模型學會正確產生那些標記，這就是為什麼聊天模型能維持連貫的多輪對話，而不是把每則訊息都當成一次全新的文本補全。

What it teaches, concretely: the model learns to treat your message as an instruction to follow rather than as text to continue, to produce answers in the expected shape (headings, lists, code blocks when appropriate), to keep a helpful tone, and to decline harmful requests when such refusals appear in the data. This is the step that turns the base text completer into something that responds to requests.

具體教了什麼：模型學會把你的訊息當成要遵循的指令，而不是要接續的文本；以預期的形式產出答案（標題、清單、適當時給程式碼區塊）；保持有幫助的語氣；以及當資料中出現這類拒絕時，回絕有害的請求。就是這一步，把基礎的文本補全器變成會回應請求的東西。

Second, *learning from preferences*. People compare several answers to the same question and mark which one is better, and the model learns from those judgments what "good" means in practice. Three names come up here; they are unpacked right below.

第二是「從偏好學習」。人們比較同一個問題的幾個答案、標出哪個比較好，而模型從這些判斷中學會「好」在實務上意味著什麼。這裡會出現三個名詞；下面立刻解釋。

*RLHF* (reinforcement learning from human feedback) is the whole procedure, not a single algorithm. Humans rank several answers to the same question, a separate reward model learns to predict those rankings as a "goodness" score, and then the main model is trained to produce answers that earn high scores from the reward model. A penalty keeps it from straying too far from what instruction tuning taught it, so it does not learn weird tricks that merely fool the scorer. The result is the model picking up subtler preferences: helpful, honest, harmless, and appropriately detailed.

RLHF（從人類回饋的強化學習）是整套程序，不是單一演算法。人類對同一個問題的幾個答案排名，一個獨立的獎勵模型學會把那些排名預測成「好」的分數，然後主要模型被訓練去產出能從獎勵模型那裡拿高分的答案。有一項懲罰讓它不要偏離指令微調教給它的東西太遠，這樣它就不會學到那些只是在騙過評分者的怪招。結果是模型領會到更細微的偏好：有幫助、誠實、無害、詳細程度恰當。

*PPO* (Proximal Policy Optimization) is the reinforcement learning method usually used inside RLHF to nudge the main model. It works in small steps: the model generates answers, the reward model scores them, and the model's parameters are updated a little in the direction of better-scoring answers. The "proximal" part means each update is kept small, and that is what stops the model from changing too drastically in one go and forgetting what it already knows.

PPO（近端策略最佳化）是 RLHF 內常用來推動主要模型的強化學習方法。它以小步運作：模型產生答案、獎勵模型評分、模型的參數朝著得分較好的答案方向更新一點點。「近端」的意思是每次更新都保持很小，正是這一點防止模型一次改變太劇烈、忘掉它已經會的東西。

*DPO* (Direct Preference Optimization) is the simpler modern alternative that skips both the reward model and PPO. Instead of training a scorer first, it takes the preference pairs directly (this answer is better than that one) and adjusts the model so the preferred answer becomes more likely than the rejected one. Fewer moving parts, more stable in practice, and it is what many current open models use.

DPO（直接偏好最佳化）是更簡單的現代替代方案，跳過獎勵模型和 PPO。它不先訓練評分器，而是直接取用偏好配對（這個答案比那個好），調整模型，讓被偏好的答案比被拒絕的答案更可能出現。活動零件更少、實務上更穩定，是目前許多開源模型採用的方法。

RLHF is the overall recipe of learning from human rankings, PPO is the classic engine that applies those rankings, and DPO is the newer shortcut that applies the rankings directly without a separate scorer.

RLHF 是從人類排名學習的整體配方，PPO 是套用那些排名的經典引擎，而 DPO 是較新的捷徑，不經獨立評分器直接套用排名。

Third, *constitutional AI*, or learning from AI feedback. Instead of paying humans to rank answers, a stronger model critiques and revises its own answers against a written set of principles, and the improved answers become training data. This scales alignment without expensive human labeling.

第三是「憲法式 AI」，也就是從 AI 回饋學習。它不花錢請人為答案排名，而是讓更強的模型對照一份寫好的原則清單，批評並修訂它自己的答案，改進後的答案成為訓練資料。這讓對齊能擴展規模，而不需要昂貴的人工標註。

The "constitution" is a short written list of principles, authored by people but applied by the model. Typical entries say things like "choose the response that is most helpful", "do not assist with harmful acts", or "be honest about uncertainty". The principles are the only human input in the loop; everything else is done by models.

這份「憲法」是一份短短的書面原則清單，由人撰寫、由模型套用。典型的條目像「選擇最有幫助的回應」、「不要協助有害的行為」、「對不確定誠實」。原則是這個迴圈中唯一的人類輸入；其他一切都由模型完成。

The procedure has two phases. In the first, sometimes called critique and revise, the model is given a prompt, one of its own draft responses, and one principle from the constitution. It is asked to explain how the response violates or follows the principle, and then to rewrite the response so that it complies. The rewritten responses become new supervised training data, so the model learns to produce compliant answers directly, without needing the critique step when it is actually used.

程序分兩階段。第一階段有時稱為「批評與修訂」：給模型一個提示、一份它自己草擬的回應、以及憲法中的一條原則。要它解釋這份回應如何違反或遵循該原則，然後改寫回應讓它合規。改寫後的回應成為新的監督訓練資料，於是模型學會直接產出合規的答案，實際使用時不再需要批評那個步驟。

In the second phase, the AI plays the role of the labeler. Given a prompt and two candidate responses, the model is asked which response better follows the constitution, and that judgment becomes a preference label. Many such labels train the reward model, or feed DPO directly, and the policy is then optimized exactly as in RLHF. This is RLAIF, reinforcement learning from AI feedback. Because AI-generated labels are cheap, the pipeline can scale to far more comparisons than human labeling allows, and whenever the desired behavior changes, the constitution can be edited and the whole loop rerun.

第二階段，AI 扮演標註者的角色。給它一個提示和兩個候選回應，問模型哪個回應更符合憲法，這個判斷就成了偏好標籤。大量這樣的標籤拿去訓練獎勵模型，或直接餵給 DPO，然後策略就照 RLHF 的方式最佳化。這就是 RLAIF——從 AI 回饋的強化學習。由於 AI 產生的標籤很便宜，整條管線能擴充到遠超人工標註所能負擔的比較數量；而每當想要的行為改變，只要編輯憲法、重跑整個迴圈即可。

In practice the two are often mixed: human feedback for the hardest or most safety-critical cases, AI feedback for the long tail. The main benefit is cost and scale. Alignment still depends on the quality of the principles and on the judgment of the model applying them, so a poorly written constitution produces confidently wrong behavior.

實務上兩者常混合使用：最難或最攸關安全的案例用人類回饋，長尾用 AI 回饋。主要好處是成本與規模。對齊仍然取決於原則的品質，以及套用它們的模型的判斷，所以一份寫得糟的憲法會產生自信卻錯誤的行為。

There are also more specialized post-training steps, each with its own job:

還有更專門的後訓練步驟，各司其職：

- Chat templates and system prompts, so conversations are formatted consistently.

  對話模板與系統提示，讓對話的格式一致。

- Tool use and function calling training, so the model learns to call external programs (covered in the next section).

  工具使用與函式呼叫訓練，讓模型學會呼叫外部程式（下一節詳述）。

- Long-context training, so it can work through very long documents.

  長上下文訓練，讓它能處理很長的文件。

- Routing training for mixture-of-experts models, so the right sub-network activates for each input.

  混合專家模型的路由訓練，讓每個輸入都啟動正確的子網路。

- Quantization-aware training, which prepares the model to run in a compressed form on smaller machines.

  量化感知訓練，讓模型準備好以壓縮形式在較小的機器上運行。

- Distillation, where a smaller student model is trained to imitate a larger teacher.

  蒸餾：訓練一個較小的學生模型去模仿一個較大的教師模型。

Put together, the pipeline looks like this: raw text produces a base model through pre-training; instruction data produces an instruction-following model through fine-tuning; preference data, through a reward model and reinforcement learning (or DPO directly), produces an aligned model; and tool use, long-context, and domain training produce the final assistant.

整條管線合起來是這樣：原始文本經由預訓練產出基礎模型；指令資料經由微調產出遵循指令的模型；偏好資料經由獎勵模型與強化學習（或直接 DPO）產出對齊的模型；工具使用、長上下文與領域訓練產出最終的助手。

Post-training quality often matters more than raw size: a well-taught smaller model can outperform a poorly taught much larger one at following instructions. One of the most useful things post-training can teach is how to use tools, which is the next step.

後訓練的品質往往比原始規模更重要：一個教得好的小模型在遵循指令上可以勝過一個教得差的大得多的模型。後訓練能教的最有用的事情之一是怎麼使用工具，這就是下一步。

### 1.3 Teaching the model to use tools and act like an agent — 教模型使用工具、像代理人一樣行動

The same post-training idea extends to tools. To a model, using a tool is just a format it learns, like filling in a form. The base model already knows how to search, calculate, and reason in text. What it needs to learn is when to call an external tool, which tool, and with what arguments.

同一個後訓練的想法延伸到工具。對模型來說，使用工具只是它學會的一種格式，就像填表一樣。基礎模型已經會在文本中搜尋、計算和推理。它需要學的是：何時呼叫外部工具、呼叫哪一個、帶什麼參數。

The training data for this looks like a conversation with tool calls mixed in. Someone asks for the weather in Tokyo, the assistant says it will check, calls a get_weather tool with the city as argument, receives the result, and then answers in plain language. Thousands of such examples, across many different tools, teach the pattern. The data also includes negative examples, moments where the right move is to use no tool at all, just to chat or answer directly.

這部分的訓練資料看起來像一場混入工具呼叫的對話。有人問東京的天氣，助手說它去查一下，用城市作為參數呼叫 get_weather 工具，收到結果，然後用白話回答。數千個這樣的範例、橫跨許多不同的工具，教會這個模式。資料也包含反面範例——正確做法是完全不用工具、只是聊天或直接回答的時刻。

Agent behavior goes further. Real tasks need multiple rounds, so the training also includes full *trajectories*: long sequences of thought, tool call, tool result, next thought, next tool call, and a final answer. Such trajectories come from several sources: people recorded using tools to solve tasks; a strong teacher model generating example solutions; and the model generating its own solutions while keeping only the ones that succeed (self-play and rejection sampling). A common style is ReAct, short for reasoning and acting, where the model writes a thought, then an action, then reads the observation, and repeats. Writing the thought out each round is what makes long multi-step tasks reliable:

代理人行為更進一步。真實任務需要多個回合，所以訓練也包含完整的「軌跡」：長長的序列——思考、工具呼叫、工具結果、下一個思考、下一個工具呼叫、以及最終答案。這些軌跡來自幾個來源：錄下人們使用工具解題的過程；強大的教師模型生成範例解法；以及模型自己生成解法、只保留成功的那些（自我對弈與拒絕採樣）。一種常見風格是 ReAct——推理與行動的縮寫——模型寫下一個想法、接著一個行動、讀取觀察，然後重複。每回合都把想法寫出來，正是長的多步驟任務得以可靠的原因：

```
Thought: I need to find who won the 2023 Nobel Prize in Physics, then their universities.
Action: search for the 2023 Nobel Prize in Physics winners.
Observation: the prize went to Pierre Agostini, Ferenc Krausz, and Anne L'Huillier.
Thought: now I need their affiliations.
Action: search for their universities.
Observation: Ohio State University, the Max Planck Institute, and Lund University.
Final answer: the 2023 laureates are affiliated with Ohio State, Max Planck, and Lund.
```

```
Thought: 我需要找出誰獲得 2023 年諾貝爾物理學獎，然後查他們的大學。
Action: 搜尋 2023 年諾貝爾物理學獎得主。
Observation: 獎項頒給 Pierre Agostini、Ferenc Krausz 和 Anne L'Huillier。
Thought: 現在我需要他們的所屬機構。
Action: 搜尋他們的大學。
Observation: 俄亥俄州立大學、馬克斯·普朗克研究所、隆德大學。
Final answer: 2023 年得主分別隸屬於俄亥俄州立、馬克斯·普朗克和隆德。
```

Tool use also gets its own reinforcement learning, but here the rewards can be exact rules instead of human opinions: did the final answer match the ground truth, did the tool call execute without error, were the arguments semantically correct, was the format valid, and was the task finished with as few calls as possible. Methods such as PPO or GRPO optimize against these signals. The training data deliberately includes failures: rate limits, invalid arguments, timeouts, and wrong tool names, together with recoveries such as retrying with corrected arguments, switching to a different tool, or asking the user. An agent that has seen failures in training handles them calmly in practice. Complex tasks also benefit from planning data, where the model first writes a step-by-step plan and then executes it one step at a time.

工具使用也有自己的強化學習，但這裡的獎勵可以是確切的規則而不是人的意見：最終答案是否符合標準答案、工具呼叫是否無錯誤地執行、參數在語意上是否正確、格式是否有效、任務是否用盡可能少的呼叫完成。PPO 或 GRPO 之類的方法對著這些訊號最佳化。訓練資料刻意包含失敗：速率限制、無效參數、逾時、錯誤的工具名稱，以及各種復原方式——用修正過的參數重試、換一個工具、或詢問使用者。一個在訓練中見過失敗的代理人，在實務上能冷靜處理失敗。複雜任務也受益於規劃資料：模型先寫出逐步計畫，然後一步一步執行。

The model is trained on many different tools across many domains (web, code, data, APIs, math), so it learns the general pattern of tool use and can handle tools it has never seen by reading their descriptions. And because high-quality example trajectories are expensive, most teams build a synthetic data pipeline:

模型在跨越許多領域（網頁、程式碼、資料、API、數學）的許多不同工具上訓練，所以它學會工具使用的一般模式，能透過閱讀描述來處理它從未見過的工具。而且由於高品質的範例軌跡很昂貴，大多數團隊會建立一條合成資料管線：

1. Define the tool descriptions.

   定義工具描述。

2. Generate diverse example requests.

   生成多樣的範例請求。

3. Have a teacher model produce solutions.

   讓教師模型產出解法。

4. Execute the tools to get real results.

   執行工具取得真實結果。

5. Keep only the successful trajectories.

   只保留成功的軌跡。

6. Add error cases and edge cases.

   加入錯誤案例與邊界案例。

7. Fine-tune the model on the filtered data.

   用篩選後的資料微調模型。

8. Run reinforcement learning with execution feedback.

   以執行回饋跑強化學習。

9. Repeat, with the improved model generating better data each round.

   重複，讓改進後的模型每一輪生成更好的資料。

The base model already knows how to reason. Post-training teaches it when and how to call external tools in a structured, reliable way, and the quality of the example trajectories plus the execution feedback matters more than the specific algorithm. Training gives the model the ability to act; how much of that ability you actually get depends on how you set things up on your side, which is the next section.

基礎模型本來就會推理。後訓練教它何時、以及如何以結構化而可靠的方式呼叫外部工具，而範例軌跡加上執行回饋的品質，比用哪個演算法更重要。訓練給了模型行動的能力；你實際能拿到多少這份能力，取決於你那邊怎麼設定，這是下一節的內容。

## 2. How to get a model to do work for you — 怎麼讓模型為你工作

### 2.1 The idea of an agent — 代理人的概念

A chatbot answers one message at a time, which is fine for conversation. Real tasks need several rounds: look something up, read the result, decide what to do next, do it, check the outcome. An *agent* is the loop that does this. The difference from a chatbot is *agency*: once you give it a goal, it keeps pursuing that goal instead of only reacting to your last message. It is self-standing, too; you hand over the task once and it runs step after step on its own, and you check in at the end or when it needs you. Picture a person working through a problem with a notebook.

聊天機器人一次回一則訊息，對聊天來說沒問題。真實任務需要好幾個回合：查點東西、讀結果、決定下一步做什麼、去做、檢查結果。「代理人」就是做這件事的迴圈。它和聊天機器人的差別在於「能動性」：你一旦給它一個目標，它會持續追求那個目標，而不是只對你最後一則訊息做反應。它也是獨立運作的；你交出任務一次，它就自己一步一步跑下去，你在最後、或在它需要你的時候才查看。想像一個人拿著記事本解一道題。

The path is not fixed in advance. The loop is dynamic and adaptive: each round it reads what it just learned and picks the next move from that. An empty search gets rephrased, a failed tool call goes to a different tool, and if you interrupt with "actually, I prefer morning flights", it folds that in and replans. The plan emerges from the observations rather than from a script, so a surprise does not break it. Each round has the same simple shape: think, act (usually a tool call), read the result, update the plan, repeat until the agent judges the task done. The model is the brain, the tools are the hands, and the notes it keeps along the way are that notebook. Knowing when to stop is part of the job as well, which is why the next section covers stop conditions: an agent with no sense of "done" will keep calling tools forever.

路徑不是事先定好的。這個迴圈是動態而調適的：每一回合它讀進剛學到的東西，從中挑出下一步。搜尋落空就換個說法、工具呼叫失敗就換另一個工具；如果你插話說「其實我比較想要早上的班機」，它會把這點納入並重新規劃。計畫是從觀察中浮現的，而不是從劇本來的，所以意外不會讓它當機。每一回合都是同一個簡單形狀：思考、行動（通常是工具呼叫）、讀結果、更新計畫、重複，直到代理人判斷任務完成。模型是大腦，工具是雙手，它一路記下的筆記就是那本記事本。知道何時停止也是工作的一部分，所以下一節會講停止條件：一個沒有「完成」概念的代理人會永遠不停地呼叫工具。

### 2.2 Basic instructions that make the agent reliable — 讓代理人可靠的基本指令

None of this is exotic. Models are trained on examples of exactly this kind of work, so a few habits on your side go a long way:

這些都不是什麼奇技淫巧。模型就是在這種工作的範例上訓練出來的，所以你這邊養成幾個習慣就很有用：

- Describe the end goal and the constraints, with clear success criteria. "Find the 2024 revenue of Apple and Microsoft, compare them, and show your sources" works far better than "find me info about companies." Say what format you want and what limits apply (budget, time, length).

  描述最終目標和約束，附上清楚的成功標準。「找出蘋果和微軟 2024 年的營收、比較它們、並附上你的來源」遠比「幫我找一些公司的資訊」有效。說出你要什麼格式、有哪些限制（預算、時間、長度）。

- Ask it to reason out loud before each action. A standing instruction like "before each tool call, explain what you are looking for and why you chose this tool" activates the step-by-step behavior it was trained on.

  請它在每次行動前把推理說出來。像「每次呼叫工具之前，說明你在找什麼、為什麼選這個工具」這樣的常設指令，會啟動它被訓練出來的逐步行為。

- Break big tasks into smaller ones. "Plan a three-day trip for two people within 2000 dollars" is hard in one shot; finding flights, then hotels, then attractions, then assembling an itinerary is four manageable tasks. Splitting also protects long tasks from losing focus as the conversation grows.

  把大任務拆成小任務。「為兩個人規劃一趟 2000 美元以內的三天旅行」很難一次做到；先找機票、再找飯店、再找景點、再組裝行程，是四個可管理的任務。拆分也能保護長任務，不讓它在對話變長時失去焦點。

- Tell it how to handle failure. "If a tool call fails, explain what went wrong and try another approach; do not give up after one failure" prevents the common pattern of a single error ending the whole task.

  告訴它怎麼處理失敗。「如果工具呼叫失敗，說明出了什麼問題、換一種做法；不要一次失敗就放棄」能防止「一個錯誤就結束整個任務」這種常見模式。

- Set stop conditions. "Use at most five tool calls," "if you cannot verify something with a tool, say so instead of guessing," or "ask me when you need input" prevents runaway loops, wasted calls, and confident made-up answers.

  設定停止條件。「最多用五次工具呼叫」、「如果無法用工具查證某件事，就直說而不是猜」、或「需要我提供資訊時就問我」，能防止失控的迴圈、浪費的呼叫、和自信的編造答案。

- For long conversations, summarize progress now and then. "So far we found flights at 400 dollars departing 8 am and hotels at 120 per night; now find restaurants near the hotel." Models have a fixed amount of attention, and a short summary keeps earlier findings alive.

  對長對話，偶爾總結進度。「到目前為止我們找到 400 美元、早上 8 點起飛的機票，和每晚 120 的飯店；現在找飯店附近的餐廳。」模型的注意力是固定的，一小段總結能讓早先的發現活著。

- Ask for structured output when you need to check or reuse the result: "answer with the fields answer, sources, confidence, and limitations."

  當你需要檢查或重用結果時，要求結構化輸出：「以 answer、sources、confidence、limitations 四個欄位回答。」

If you build the agent yourself, write detailed tool descriptions: what the tool does, what it returns, examples of arguments, and what it should not be used for. Models pick tools far better when the description reads like a routing rule. Match the model to the task: a small fast model handles one or two tool calls. Complex multi-step reasoning wants a larger or reasoning-specialized model. Code-heavy work wants a code-trained model. Very long tasks want a model with a large context window. Cost-sensitive work favors the smaller model with careful prompting.

如果你親手打造代理人，請寫詳細的工具描述：這個工具做什麼、回傳什麼、參數的範例、以及它不該被用來做什麼。當描述讀起來像一條路由規則時，模型挑工具會準得多。讓模型與任務相配：一兩次工具呼叫，小而快的模型就夠。複雜的多步推理要較大的、或專精推理的模型。大量寫程式的工作要以程式碼訓練的模型。很長的任務要有大上下文視窗的模型。在意成本的工作適合較小的模型加上細心的提示。

Finally, always verify the agent's work. Check that it called the right tool with valid arguments, that the final answer uses the tool results rather than ignoring them, and that claims are backed by something it retrieved. Red flags: repeated failed calls with no recovery, answers that contradict earlier results, and final answers that ignore what the tools returned. Instructions like these cover a single conversation. When the same job comes up again and again, you want something more permanent, and that is a skill.

最後，永遠要驗證代理人的工作。檢查它是否用有效的參數呼叫了正確的工具、最終答案是否採用了工具結果而不是忽略它們、以及它的說法是否有它取回的東西支持。警訊：重複失敗卻沒有復原的呼叫、與先前結果矛盾的答案、以及忽略工具回傳內容的最終答案。這樣的指令涵蓋的是單一場對話。當同一份工作一再出現時，你要的是更持久的東西，那就是技能。

### 2.3 Skills: teaching the agent one specific job — 技能：教代理人一件特定的工作

A *skill* is a folder on disk that teaches the agent how to do one specific task or work in one specific domain: filling in PDF forms, querying a particular database, writing in your company's style. Think of it as a capability plugin that lives in files rather than in the model's memory: a laminated card in a drawer that you only take out when the job calls for it. A skill can bundle more than instructions: small programs the agent can run, reference documents it can read on demand, and example files or templates.

「技能」是磁碟上的一個資料夾，教代理人如何做一件特定的任務、或在一個特定領域工作：填寫 PDF 表單、查詢某個資料庫、用你公司的風格寫作。把它想成一個住在檔案裡、而不是模型記憶裡的能力外掛：一張收在抽屜裡的護貝卡片，只在工作需要時才拿出來。技能能打包的不只是指令：還有代理人可以執行的小程式、可以隨需閱讀的參考文件、以及範例檔案或模板。

The standard layout looks like this. A skill is a directory whose entry point is a file called SKILL.md. Next to it there can be a scripts folder with executable helpers, a references folder with documentation, and an assets folder with templates or data. The SKILL.md file itself has two parts. At the top, a short metadata block gives the skill a name and, most importantly, a description of what it does and when to use it. Below that, the body holds the actual instructions: when to use the skill, the steps of the job, and pointers to the reference files.

標準配置長這樣。一個技能是一個目錄，入口是一個叫做 SKILL.md 的檔案。旁邊可以有 scripts 資料夾放可執行的小工具、references 資料夾放文件、assets 資料夾放模板或資料。SKILL.md 本身分兩部分。最上方是一小段中繼資料，給技能一個名字，以及最重要的——說明它做什麼、何時使用。下面的主體是真正的指令：何時使用這個技能、工作的步驟、以及指向參考檔案的指引。

Loading happens in three levels, and this is what lets skills scale. Level one: the agent always sees only the names and one-line descriptions of all skills. That is cheap, and it lets the agent scan the whole catalog. Level two: when a task matches a description, the agent opens that skill's full instructions. Level three: the bundled scripts, references, and assets are loaded or run only as the instructions call for them. This is called progressive disclosure. It means an agent can have dozens of skills available while paying attention cost only for the one it is using right now.

載入分三個層級，這正是技能能擴展的原因。第一層：代理人永遠只看到所有技能的名稱和一行描述。這很便宜，讓代理人能掃描整個目錄。第二層：當任務吻合某個描述，代理人打開該技能的完整指令。第三層：打包的腳本、參考資料和資產，只在指令呼叫它們時才載入或執行。這叫做漸進式揭露。它意味著一個代理人可以擁有幾十個技能，卻只為此刻正在用的那一個付出注意力成本。

A few design principles keep skills healthy. Keep them self contained: a folder you can copy anywhere, with no hidden state elsewhere. Write the description as a routing rule, "use when the user needs...", because that line is the only thing the agent reads before deciding to open the skill. Keep the body lean and push long reference material into the references folder. And prefer scripts over prose for mechanical steps, because a program does the same thing every time while instructions can be misread.

幾條設計原則讓技能保持健康。保持自足：一個你可以複製到任何地方的資料夾，別處沒有隱藏的狀態。把描述寫成一條路由規則：「當使用者需要……時使用」，因為在決定打開技能之前，代理人讀到的只有那一行。主體保持精瘦，把長篇參考資料推進 references 資料夾。機械性的步驟寧可用腳本而不用散文，因為程式每次做同樣的事，而指令可能被讀錯。

A skill is only useful if it can change, and since a skill is just files, changing it is easy. That is where an agent's learning actually happens.

技能只有在能改變時才有用，而技能既然只是檔案，改變它很容易。代理人的學習實際上就發生在這裡。

### 2.4 Learning with skills: editing the files — 用技能學習：編輯檔案

Now, what does "learning" mean with skills? It does not mean retraining the model. The weights do not change, there is no gradient update. When we say the agent learned from a skill, we mean a durable change was made to the skill files on disk, so the next similar task goes better. It is closer to a person updating a checklist or runbook than to studying for an exam. It also differs from in-context learning, which lives only inside the current conversation and dies when the conversation ends.

那麼，有了技能之後，「學習」是什麼意思？它不是重新訓練模型。權重沒有變，沒有梯度更新。當我們說代理人從一個技能學到了東西，我們的意思是磁碟上的技能檔案被做了一次持久的更動，所以下一個類似的任務會做得更好。它比較像一個人更新檢查清單或操作手冊，而不是像準備考試。它也不同於上下文內學習——後者只活在當前對話裡，對話結束就消失。

Improving a skill happens through three edit operations. *Append* adds new content: a new step, a script, an edge case that came up, a worked example worth keeping. *Refine* rewrites existing content: fix a wrong step, sharpen the description so it triggers correctly, generalize a rule that was too specific. *Remove* deletes what is obsolete or harmful: dead scripts, outdated steps, misleading rules. A skill that only ever grows becomes bloated and contradictory, so all three operations are needed.

改進一個技能靠三種編輯操作。「新增」加入新內容：一個新步驟、一支腳本、一個出現過的邊界案例、一個值得保留的完整範例。「精修」改寫既有內容：修正錯誤的步驟、把描述磨利讓它正確觸發、把太特定的規則一般化。「移除」刪掉過時或有害的東西：失效的腳本、過期的步驟、誤導的規則。一個只增不減的技能會變得臃腫而自相矛盾，所以三種操作都需要。

The full learning loop around those edits looks like this:

圍繞這些編輯的完整學習迴圈長這樣：

1. Act: run the task using the skill.

   行動：用這個技能執行任務。

2. Observe: did it succeed? Where did it stumble, guess, or need help?

   觀察：成功了嗎？它在哪裡卡住、亂猜、或需要幫助？

3. Reflect: diagnose the gap. Missing knowledge means append, wrong or ambiguous knowledge means refine, stale knowledge means remove.

   反思：診斷落差。缺知識代表新增、錯的或含糊的知識代表精修、過期的知識代表移除。

4. Propose: draft the concrete change, not a vague intention.

   提案：草擬具體的更動，而不是模糊的意圖。

5. Apply: make the edit.

   套用：做出編輯。

6. Verify: re-run the task or the tests to confirm the change helps and does not break anything else. This step is what separates learning from mere editing.

   驗證：重跑任務或測試，確認這個更動有幫助、也沒有弄壞別的東西。就是這一步把學習和純編輯區分開來。

7. Persist and version: save the change with a note of where it came from, so a bad lesson can be reverted.

   保存與版控：保存更動並註記它從何而來，讓錯誤的一課可以被復原。

Who carries out this loop, the agent or you? There are three modes. Agent-only: the agent notices a gap during a task and edits its own skill. That is fast and scales, but it risks learning a wrong lesson from one unusual task, drifting, or being fooled by malicious text inside a skill file, so it needs guardrails like change logs, sandboxes, and review. User-only: a person writes and maintains the skill. Reliable and fully controlled, but slow, and the human often never sees the failure modes the agent hits in practice. Cooperative, which is what most real setups converge on: the agent proposes the specific change and explains its rationale, citing the failure that motivated it, and you review, edit, or reject. The rule of thumb: the more consequential the skill and the harder the task is to verify, the more the loop should shift toward human approval. Low-stakes, well-tested domains can safely run autonomously. Skills are one piece of the bigger setup around the model, and that whole setup has a name: the harness.

誰來執行這個迴圈，代理人還是你？有三種模式。純代理人：代理人在任務中注意到落差，編輯自己的技能。這很快、能擴展，但有從單一特殊任務學到錯誤教訓、漂移、或被技能檔案裡的惡意文字欺騙的風險，所以需要變更日誌、沙箱、審查之類的護欄。純使用者：由人撰寫並維護技能。可靠、完全可控，但很慢，而且人往往看不到代理人在實務上撞到的失敗模式。協作模式——大多數真實設定最終都會走到這裡：代理人提出具體的更動並解釋理由，引用促使它這麼做的失敗案例，由你審查、編輯或拒絕。經驗法則是：技能的後果越大、任務越難驗證，迴圈就越應該偏向人工核准。低風險、測試充分的領域可以安全地自主運行。技能是模型周邊那套更大設定的一部分，而那整套設定有個名字：駕馭。

### 2.5 The agent harness: the software around the model — 代理人駕馭：模型周圍的軟體

An *agent harness* (also called agent scaffolding) is the software infrastructure surrounding the model that makes it operate as an agent. The formula is simple: agent = model + harness. A model on its own is a stateless function from text to text. It cannot call tools, remember anything between calls, or act over many rounds. The harness manages tool use, memory, state, execution environments, and feedback loops; those are the things the model's own reasoning does not cover. A single question-and-answer exchange needs no harness, but the harness becomes the important part as soon as tasks grow multi-step, tool-oriented, or long-running, which is exactly the kind of task from section 2.1.

「代理人駕馭」（也叫代理人骨架）是包圍著模型、讓它以代理人方式運作的軟體基礎設施。公式很簡單：代理人＝模型＋駕馭。單獨的模型是一個無狀態的、從文本到文本的函式。它不能呼叫工具、不能在兩次呼叫之間記住任何東西、不能跨越多個回合行動。駕馭管理工具使用、記憶、狀態、執行環境和回饋迴圈——那些都是模型自身的推理不涵蓋的事。單純一問一答不需要駕馭，但任務一變成多步驟、工具導向、或長時間運行，駕馭就成了重要的部分，而那正是 2.1 節講的那種任務。

Concretely, the harness assembles what the model sees each round (the system prompt, the conversation, retrieved material), registers the available tools and dispatches the tool calls the model asks for, runs them in a sandbox or workspace, feeds the results back into the next round, and keeps the agent's state outside the model's context window so the transcript does not have to grow forever. It also enforces guardrails: scoped permissions, approval steps, monitoring, and a decision about when to stop. Because the model inside is non-deterministic, a good harness also recovers gracefully when the model invents a tool call or claims the task is finished when it is not.

具體來說，駕馭組裝模型每一回合看到的東西（系統提示、對話、取回的材料），註冊可用的工具並派發模型要求的工具呼叫，在沙箱或工作區中執行它們，把結果餵回下一回合，並把代理人的狀態保存在模型的上下文視窗之外，讓對話記錄不必無止境地增長。它也執行護欄：範圍化的權限、核准步驟、監控、以及何時停止的判斷。由於裡面的模型並非決定性的，好的駕馭還能優雅地復原——當模型編造出一個工具呼叫、或任務還沒做完就宣稱完成了的時候。

There are two layers. The inner harness ships with the product: the agent SDK, the loop, the built-in tools. The outer harness is what you assemble around it: instruction files, custom skills (section 2.3), MCP servers, and memory stores. Within that, guides steer the agent before it acts (your instructions and skills are guides), while sensors check the result afterward and let it self-correct. Sensors can be deterministic, like tests and linters, or inferential, like another model judging the output.

駕馭有兩層。內層駕馭隨產品附帶：代理人 SDK、迴圈、內建工具。外層駕馭是你圍著它組裝的東西：指令檔案、自訂技能（2.3 節）、MCP 伺服器、記憶儲存。在其中，「導引」在代理人行動前牽引它（你的指令和技能就是導引），「感測器」在事後檢查結果、讓它自我更正。感測器可以是決定性的，像測試和 linter；也可以是推斷性的，像用另一個模型來評判輸出。

You can see how differently harnesses are shaped by looking at five of them, each built for a different job.

看看五個為不同工作而造的駕馭，你就能看到駕馭的形狀有多不同。

LangChain and LangGraph are the framework case, where you are the harness designer. Their purpose is letting developers build custom agents for any domain, so the harness is programmable rather than fixed. LangChain gives you tool registries, prompt templates, memory modules, and an executor that runs the model-tool loop: the model proposes a tool call, the executor runs it, and the result goes back into the next round. LangGraph goes one level lower: the agent is an explicit graph of nodes and edges over a typed state, with checkpoints so a run can pause, resume, or ask a human in the middle of the loop. Here the loop, the state, and the persistence are objects you define in code, which is what makes it suited to wiring agents into your own software.

LangChain 和 LangGraph 是框架那一例，你是駕馭的設計者。它們的目的是讓開發者為任何領域打造自訂代理人，所以駕馭是可程式化的，而不是固定的。LangChain 給你工具註冊表、提示模板、記憶模組、以及一個執行器，負責跑模型—工具迴圈：模型提出工具呼叫、執行器執行它、結果回到下一回合。LangGraph 再低一層：代理人是一張在型別化狀態之上、由節點與邊組成的明確圖，帶有檢查點，讓一次運行可以暫停、恢復、或在迴圈中間詢問人類。這裡的迴圈、狀態和持久化都是你在程式碼中定義的物件，這正是它適合把代理人接進你自己軟體的原因。

Claude Code is a coding harness, shaped around software tasks inside a repository. Its tools are file reading, file editing, searching, and shell commands, and its guardrails are a permission system that asks before risky actions, plus a read-only plan mode for safe exploration. It reads instruction files (CLAUDE.md) as standing orders, keeps a todo list so long tasks stay on track, and compacts the conversation when the context window fills, because a codebase is far bigger than any context window. Tests and linters act as sensors that send it back to fix what it broke.

Claude Code 是一個程式設計駕馭，圍繞儲存庫內的軟體任務塑形。它的工具是讀檔、編輯檔案、搜尋和 shell 指令，它的護欄是一套在危險行動前先詢問的權限系統，外加一個供安全探索的唯讀計畫模式。它把指令檔案（CLAUDE.md）當成常設命令來讀，維護一份待辦清單讓長任務不偏離軌道，並在上下文視窗填滿時壓縮對話，因為程式碼庫遠大於任何上下文視窗。測試和 linter 充當感測器，把它送回去修好它弄壞的東西。

OpenClaw is an always-on personal assistant harness. Its job is to live in your chat apps (WhatsApp, Telegram, Discord, Slack, and similar) and help you day to day, so its harness is a gateway process that keeps sessions alive across messages and channels. Instead of relying on the context window, it keeps memory in files, a MEMORY.md plus daily notes, so it remembers you between sessions, and it adds a scheduler for cron jobs and proactive heartbeat messages, plus skills and browser or shell tools. State lives in files and a small local database, and the agent picks up where it left off.

OpenClaw 是一個全天候運作的個人助理駕馭。它的工作是住在你的聊天軟體裡（WhatsApp、Telegram、Discord、Slack 之類），日常協助你，所以它的駕馭是一個讓工作階段跨越訊息與頻道保持存活的閘道程序。它不依賴上下文視窗，而是把記憶放在檔案裡——一個 MEMORY.md 加每日筆記——所以它在工作階段之間記得你；它還加上一個負責排程工作和主動心跳訊息的排程器，外加技能和瀏覽器或 shell 工具。狀態住在檔案和一個小型本地資料庫裡，代理人從它上次停下的地方接續。

NotebookLM is a "talk to your documents" harness. You upload PDFs, links, audio, and notes into a notebook, and the harness parses and indexes them into a private retrieval store. Every question triggers retrieval over that store, and the answer is constrained to the retrieved passages with citations pointing back to the exact spots, which is what makes it dependable for studying and research. On top of question answering, the same harness generates artifacts from your sources: study guides, FAQs, timelines, mind maps, and audio overviews.

NotebookLM 是一個「和你的文件對話」的駕馭。你把 PDF、連結、音訊和筆記上傳進一本筆記本，駕馭把它們解析並索引進一個私有的檢索儲存庫。每個問題都會觸發對那個儲存庫的檢索，而答案被限制在取回的段落內、附帶指向確切位置的引註，這正是它在學習與研究上可靠的原因。除問答之外，同一個駕馭還能從你的來源生成各種產物：學習指南、常見問題、時間軸、心智圖、音訊導覽。

Deep research tools (Google's Deep Research, OpenAI's deep research mode, and similar) are research harnesses. Their job is to turn a broad question into a cited report, so the harness runs as an asynchronous background job rather than a chat. First the model writes a research plan, then the harness loops over web search and page reading for many rounds, keeping notes in a scratchpad, then reviews its own findings for gaps and searches again, and finally synthesizes everything into a structured report with inline citations. The loop is long, minutes and dozens of steps, so the harness also reports progress and lets you steer mid-run.

深度研究工具（Google 的 Deep Research、OpenAI 的深度研究模式之類）是研究駕馭。它們的工作是把一個寬泛的問題變成一份附引註的報告，所以駕馭以非同步的背景任務運行，而不是一場聊天。模型先寫一份研究計畫，然後駕馭在網頁搜尋與頁面閱讀之間來回跑好幾回合、在草稿本裡記筆記，接著檢查自己的發現有沒有缺口、再搜尋一輪，最後把一切綜合成一份有行內引註的結構化報告。迴圈很長——幾分鐘、幾十個步驟——所以駕馭也會回報進度，讓你在半途引導它。

The pattern across all five: the harness is shaped by the job. The loop, the tools, where state lives, and the guardrails all change with the purpose, and the model underneath can be the same family.

五者共通的模式是：駕馭由工作塑形。迴圈、工具、狀態住在哪裡、護欄，全都隨目的而變，而底下的模型可以是同一個家族。

Different products are mostly different harnesses wrapped around similar models. When an agent handles a real task well or badly, the difference usually lies in the harness, the tools it is given, the sandbox, and the guardrails, not in the model alone. And since the outer harness is files and configuration, you can improve it without touching the model: better instructions, better skills, better sensors. That is also where things go wrong if nobody maintains it. All of that maintenance only pays off because the agent can remember things between sessions, and that memory is what makes it grow over time. That is the last section.

不同的產品，多半只是包著相似模型的不同駕馭。當一個代理人把真實任務處理得好或不好，差別通常在駕馭、給它的工具、沙箱和護欄，而不是只在模型。而且由於外層駕馭是檔案與設定，你可以在不碰模型的情況下改進它：更好的指令、更好的技能、更好的感測器。如果沒有人維護，這裡也正是出問題的地方。所有那些維護之所以值得，是因為代理人能在工作階段之間記住事情，而那份記憶正是讓它隨時間成長的東西。這就是最後一節。

## 3. The growing agent: data, memory, environment, and you — 成長中的代理人：資料、記憶、環境，與你

### 3.1 What memory is, in general — 記憶一般是什麼

You already use memory every day: you remember roughly where you parked the car, and that record changes where you walk in the lot. Formally, memory is any record of a past event that changes future behavior. Three parts matter. First, a trace: some event leaves a lasting alteration in something, physical or mental. Second, causal power: the trace must bias how the system responds later, otherwise it is mere residue. Third, a reader: a trace becomes memory when something later reads it and is changed by it. A footprint nobody ever meets is a latent record, not yet a memory.

你每天都在用記憶：你記得車大概停在哪裡，而那筆記錄改變了你在停車場裡走的方向。正式地說，記憶是任何「會改變未來行為的過去事件記錄」。三個部分要緊。第一，痕跡：某個事件在某樣東西上留下持久的改變，無論是物理的還是心智的。第二，因果力量：這道痕跡必須對系統日後的反應產生偏向，否則它只是殘渣。第三，讀者：當後來有東西讀到這道痕跡、並被它改變，痕跡才成為記憶。一個沒有人會遇上的腳印，是一份潛在的記錄，還不是記憶。

Two properties follow. Memory is always lossy and reconstructive, never playback: every record is partial and degrades, so recalling rebuilds the past rather than replaying it. And memory requires an arrow of time: recording costs entropy, so no memory exists in a world without irreversible processes.

由此得到兩個性質。記憶永遠是有損的、重建式的，從不是回放：每份記錄都是局部的、會劣化，所以回憶是重建過去，而不是重播過去。而且記憶需要一支時間之箭：記錄要付出熵的代價，所以在一個沒有不可逆過程的世界裡，不存在記憶。

You can ask four independent questions about any memory: what it is made of, how big the recording system is, how long it lasts, and who is doing the remembering.

對任何一份記憶，你可以問四個互相獨立的問題：它由什麼構成、記錄系統有多大、它持續多久、以及是誰在記。

- What it is made of, from physical to mental. Rock strata and isotopes are inert physical records. DNA, proteins, and epigenetic marks are chemical records that actively drive processes. Immune cells and CRISPR in bacteria are functional memory without a mind: the body remembers a pathogen and responds faster next time. Neural traces shape behavior without conscious recall. Human memory crosses a threshold: it is not only used but experienced, and each recall reinterprets the past through the present. On top of that sits reflective memory, memory of memory, which builds a continuous sense of self.

  由什麼構成——從物理到心智。岩層和同位素是惰性的物理記錄。DNA、蛋白質和表觀遺傳標記是主動驅動過程的化學記錄。免疫細胞和細菌裡的 CRISPR 是沒有心智的功能性記憶：身體記得一個病原體，下次反應更快。神經痕跡在沒有意識回想的情況下塑造行為。人類記憶跨過一道門檻：它不只被使用，還被體驗，而每次回想都透過現在重新詮釋過去。在其之上還有反思性記憶——對記憶的記憶——它建構出連續的自我感。

- How big, from atom to universe. An electron's spin retains a correlation with what happened to it. Carbon-14 records when it was formed, which is how radiocarbon dating works. DNA records billions of years of evolution. Synapses record a lifetime of experience. Writing, law, and institutions carry memory beyond any single skull. Rock layers, ice cores, and tree rings record the planet's history. A star's composition records the generations of stars that died before it. Light itself is memory: every photon arriving now is a record of a distant past event. At the largest scale, the cosmic microwave background is a fossil of the universe roughly 380,000 years after the Big Bang.

  有多大——從原子到宇宙。一個電子的自旋保留著與它遭遇之事的關聯。碳-14 記錄它何時形成，放射性碳定年就是這樣運作的。DNA 記錄數十億年的演化。突觸記錄一生的經驗。文字、法律和制度把記憶帶出任何單一頭顱之外。岩層、冰芯和年輪記錄這顆星球的歷史。一顆恆星的成分記錄了死在它之前的那幾代恆星。光本身就是記憶：此刻抵達的每個光子，都是一件久遠過去事件的記錄。在最大的尺度上，宇宙微波背景是大爆炸後約 38 萬年時的宇宙化石。

- How long, from microseconds to the age of the universe. Quantum states and molecular vibrations hold records only briefly. Neural spikes and ringing bells last seconds. Immune memory and tree rings last years. Strata, fossils, and genomes last millions of years. Isotopic records last billions. The pattern: a record persists only as long as its material is stable relative to how fast events happen, so every memory system trades detail against durability.

  持續多久——從微秒到宇宙的年齡。量子狀態和分子振動只短暫持有記錄。神經衝擊和鐘聲持續幾秒。免疫記憶和年輪持續幾年。地層、化石和基因組持續數百萬年。同位素記錄持續數十億年。圖樣是：一份記錄能存續多久，取決於它的材料相對於事件發生速度有多穩定，所以每種記憶系統都在細節與持久之間做交換。

- Who remembers, from one mind to a civilization. A personal memory lives in one brain. Shared family lore lives across a few minds kept coherent by retelling. Oral traditions and rituals live in a community. Archives, legal records, and professional norms are institutional memory, surviving the tenure of any member. Nations remember through museums, monuments, and official histories, and that curated memory shapes laws and policy. At the widest scope, written language and the accumulated scientific record are a species-scale memory that outlives every individual.

  是誰在記——從一個心智到一個文明。個人的記憶住在一個大腦裡。家族共享的傳說住在幾個心智之間，靠重述保持一致。口述傳統和儀式住在一個社群裡。檔案、法律記錄和專業規範是制度記憶，比任何成員的任期都長。國家透過博物館、紀念碑和官方歷史來記憶，而那份經過策劃的記憶塑造法律與政策。在最寬的範圍上，書寫語言和累積的科學記錄是一份物種尺度的記憶，比任何個體都活得久。

Strip away the material and the same skeleton appears everywhere: a past event alters something, the alteration persists, the persisted trace biases future behavior, the trace is lossy, and it exists only because time has a direction. The footprint, the fossil, the genome, the synapse, the strata, the national archive, and the microwave background are one idea in different matter, and all of them steer what comes next. An agent is no exception; it just wears silicon and files instead of rock and neurons.

抽掉材料，同一副骨架到處都出現：一件過去的事改變了某樣東西、改變存續下來、存續的痕跡偏向未來的行為、痕跡是有損的，而且它只因時間有方向而存在。腳印、化石、基因組、突觸、地層、國家檔案、微波背景，是同一個想法在不同物質中的樣子，而它們全都引導著接下來發生的事。代理人也不例外；它只是穿著矽和檔案，而不是岩石和神經元。

### 3.2 The memory of an agent, layer by layer — 代理人的記憶：一層一層看

An agentic system is a layered memory hierarchy, and you are one of its layers. The same skeleton holds at every layer; what changes is the material, the size, the timescale, and who remembers. Going from the slowest, largest layer to the fastest:

代理人系統是一個分層的記憶階層，而你是其中一層。同一副骨架在每一層都成立；變的是材料、大小、時間尺度、以及誰在記。從最慢、最大的那一層走向最快的：

- The model weights. The frozen parameters produced by training: a compressed, lossy record of a vast corpus of text, code, and human feedback. This is the genetic memory of the system, the equivalent of DNA. It sets the ceiling of what is possible, it changes only rarely, and as a user you almost never edit it.

  模型權重。訓練產出的凍結參數：一份對海量文本、程式碼和人類回饋的壓縮、有損記錄。這是系統的基因記憶，等同於 DNA。它設定了可能性的上限，極少改變，而身為使用者的你幾乎從不去改它。

- The context window. Everything in front of the model right now: the system prompt, the conversation so far, retrieved documents, tool outputs. This is the working memory, the RAM of the system, and the layer where reasoning happens. It is small, volatile, and dies with the session. It has a fixed size, and quality matters far more than quantity: a window full of irrelevant material drowns the signal, so most within-task failures are really context failures.

  上下文視窗。此刻擺在模型面前的一切：系統提示、到目前為止的對話、取回的文件、工具輸出。這是工作記憶，系統的 RAM，也是推理發生的那一層。它小、易失、隨工作階段結束而死。它的大小固定，而品質遠比數量重要：一個塞滿無關材料的視窗會把訊號淹死，所以大多數任務內的失敗其實是上下文失敗。
- The agent's scratchpad. The running plan, notes, intermediate results, and reasoning trace within one task. This is procedural short-term memory, the notebook from section 2.1, and it is where self-correction lives: an agent that writes down what it tried and what failed avoids repeating the mistake.

  代理人的草稿本。一個任務之內的進行中計畫、筆記、中間結果和推理軌跡。這是程序性的短期記憶，2.1 節那本記事本，也是自我更正的所在：一個把試過什麼、什麼失敗都寫下來的代理人，能避免重蹈覆轍。

- The harness. The software scaffolding around the model from section 2.5: the loop that dispatches tool calls, the sandbox, the guardrails, and the outer layer of files (system prompt, skills, memory stores, config) that persists across sessions. It is the learning substrate from section 2.4, the highest-leverage layer: for a fixed model, durable capability gains come from here.

  駕馭。2.5 節裡圍繞模型的軟體骨架：派發工具呼叫的迴圈、沙箱、護欄，以及跨越工作階段存續的那層外圍檔案（系統提示、技能、記憶儲存、設定）。它是 2.4 節的學習基底，也是槓桿最大的一層：模型固定時，持久的能力提升都來自這裡。
- The running environment. The file system, repositories, databases, and everything the agent has produced: files it wrote, version history, logs, test results. This is world memory, and a well-structured environment is a self-correcting memory. A failing test is a record that immediately biases the agent's next action; a messy environment starves it of feedback.

  執行環境。檔案系統、儲存庫、資料庫，以及代理人產出的一切：它寫的檔案、版本歷史、日誌、測試結果。這是世界記憶，而一個結構良好的環境是一份會自我更正的記憶。一個失敗的測試是一筆立刻偏向代理人下一個行動的記錄；一個混亂的環境會讓它餓死在缺乏回饋之中。

- The records and transcripts. Logs, conversation transcripts, tool-call traces, evaluation results: the raw data of every interaction. This is the episodic memory of the system, and on its own it is inert. It becomes memory only when it feeds back into a skill edit, a config change, or an environment fix. An archive nobody reads is a footprint nobody meets.

  記錄與逐字稿。日誌、對話逐字稿、工具呼叫軌跡、評估結果：每次互動的原始資料。這是系統的情節記憶，而它本身是惰性的。只有當它回饋成一次技能編輯、一次設定變更、或一次環境修復，它才成為記憶。一座沒有人讀的檔案庫，就是一個沒有人遇上的腳印。
- You, the human. The keystone layer. You carry a model of the model (what it is good at, where it fails, what it can be trusted with), episodic memory of past sessions (last time it looped on X, this approach worked, that config broke retrieval), procedural skill (writing crisp skill descriptions, decomposing tasks, structuring environments), and your standards and intent, externalized into prompts, configs, and acceptance criteria. You are genuinely part of the agent's memory, because what you know biases the system's future behavior at every other layer. And you are the only layer with write access to all the others: you write the skills, design the environment, curate the context, read the records, and choose the model.

  你，人類。拱心石那一層。你帶著一份對模型的模型（它擅長什麼、在哪裡失敗、能放心交給它什麼）、過往工作階段的情節記憶（上次它在 X 上打轉、這個做法有效、那個設定弄壞了檢索）、程序性技能（寫出俐落的技能描述、拆解任務、結構化環境），以及你的標準與意圖——被外部化成提示、設定和驗收標準。你是代理人的記憶貨真價實的一部分，因為你所知道的東西，在其他每一層都偏向系統未來的行為。而且你是唯一對其他所有層都有寫入權限的一層：你寫技能、設計環境、策劃上下文、閱讀記錄、挑選模型。

Each layer supplies something different on its own time scale, and performance is the product of all of them.

每一層在各自的時間尺度上供應不同的東西，而表現是這一切的乘積。

The central dynamic is compounding versus drift. Compounding: a good harness, a clean environment, and a skilled curator make each task slightly easier than the last. Skills sharpen, records accumulate into reusable knowledge, you learn the system's quirks, and the agent gets better every week without the weights changing. Drift: stale skills, contradictory records, a messy environment, and an inattentive curator make the agent worse, confidently repeating outdated behavior, until trust erodes and decay sets in. Drift is slow and invisible because nothing crashes; it just degrades. Memory decays unless it is maintained: skills rot, records go stale, environments drift.

核心的動態是複利式累積對漂移。複利：一套好的駕馭、一個乾淨的環境、一位熟練的管理者，讓每個任務都比上一個稍微容易一點。技能變鋒利、記錄累積成可重用的知識、你摸熟了系統的怪癖，代理人每個星期都變得更好，而權重完全沒動。漂移：過期的技能、互相矛盾的記錄、混亂的環境、心不在焉的管理者，讓代理人變差，自信地重複過時的行為，直到信任流失、衰敗開始。漂移緩慢而隱形，因為沒有東西崩潰；它只是退化。記憶不維護就會衰敗：技能腐朽、記錄過期、環境漂移。

That is the whole picture: a model in the middle, a harness around it, memory in layers, and you tending the lot. The agent grows when you tend it and drifts when you don't.

這就是全貌：中間是一個模型，周圍是它的駕馭，記憶分層，而你照料著這一切。你照料它，代理人就成長；你不照料，它就漂移。
