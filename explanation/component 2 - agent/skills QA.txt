Q: What are agent skills? What is their standard format?
A:
An agent skill is a self-contained, file-based package of instructions and optional resources that teaches an AI agent how to perform a specific task or operate in a specific domain. Think of it as a "capability plugin" that lives on disk rather than in the model's weights.

Key idea: skills turn general-purpose agents into specialists on demand, without retraining or prompt-stuffing. The agent starts with just a lightweight catalogue of skill names/descriptions, and only loads a skill's full instructions when a task actually matches it. This is called progressive disclosure — it keeps the context window small while making arbitrarily many capabilities available.

A skill can bundle not just prose instructions but also:
- Scripts (Python, shell) the agent can execute
- Reference files (docs, schemas, templates)
- Assets (data files, examples)

So a skill is more than a prompt — it's a mini-toolkit with a contract for when and how to use it.

STANDARD FORMAT (Anthropic Agent Skills convention)

A skill is a directory whose entry point is a file named SKILL.md:

my-skill/
├── SKILL.md            # required — the manifest + instructions
├── scripts/            # optional — executable helpers
│   └── do_thing.py
├── references/         # optional — docs, schemas loaded on demand
│   └── api_spec.md
└── assets/             # optional — templates, data, examples

SKILL.md structure — two parts: YAML frontmatter (metadata) and a Markdown body (instructions).

---
name: pdf-form-filler
description: Fill PDF forms programmatically. Use when the user needs to
  populate AcroForm fields, flatten a PDF, or extract form data.
---

# PDF Form Filler

## When to use this skill
Use this when ...

## How to do it
1. Read the form schema with `scripts/inspect_form.py`
2. Map user data to fields ...
3. Fill and flatten ...

## Reference
See `references/acroform_spec.md` for field types.

Frontmatter fields:
- name (required): unique identifier (typically lowercase-hyphenated)
- description (required): when/how to use the skill — this is what the agent matches against to decide whether to load it
- license, version, metadata (optional): provenance, versioning, extra info

The description is the single most important field: it's the only thing the agent sees before deciding to activate the skill, so it must clearly state what the skill does and when to use it.

THE LOADING MODEL (three levels)
1. Level 1 — metadata (name + description) is always in context. Cheap; lets the agent scan the catalogue.
2. Level 2 — SKILL.md body is loaded only when the skill is deemed relevant.
3. Level 3 — bundled files (scripts/, references/, assets/) are loaded/executed only as the instructions call for them.

This layered design is what lets an agent have dozens of skills available while only paying the token cost for the one it's actually using.

DESIGN PRINCIPLES
- Self-contained & portable — a folder you can copy anywhere; no hidden external state.
- Descriptive over prescriptive metadata — the description should read like a routing rule ("use when…").
- Keep the body lean — put long reference material in references/ (loaded on demand), not inline.
- Scripts over prose for determinism — if a step is mechanical, ship a script rather than describing it.

Q: What does "learning" mean with agent skills? How is learning carried out through refine / append / remove of skill contents? How is this process carried out — by the agent, the user, or both cooperatively?
A:
WHAT "LEARNING" MEANS HERE

Learning with skills is not model training. The model's weights don't change — there's no gradient update, no fine-tuning. Instead, learning is knowledge externalization: the agent (or user) improves future behaviour by editing the persistent, on-disk skill files. The skill directory is the memory substrate.

So "the agent learned something" concretely means: a durable change was made to a skill's contents that makes a future task go better. This is closer to how a human writes notes, updates a runbook, or fixes a checklist — the knowledge lives outside the brain, in an artifact, and is re-read when relevant.

It's also distinct from:
- In-context learning — temporary, dies with the conversation.
- Fine-tuning — changes weights, expensive, opaque.

Skill learning sits between: persistent like fine-tuning, but transparent and editable like a document.

THE THREE EDIT OPERATIONS

Append — Add new content: new instructions, a new script, a new references/ doc, a new edge-case note or worked example. Triggers: a task revealed a scenario the skill didn't cover; new tool/API; a useful example worth recording.

Refine — Rewrite/correct/tighten existing content: fix a wrong step, sharpen the description (routing), generalize an over-specific rule, deduplicate, restructure for clarity. Triggers: the skill "worked" but awkwardly; instructions were ambiguous; the description failed to trigger when it should have.

Remove — Delete obsolete or harmful content: dead scripts, outdated steps, irrelevant references, misleading rules. Triggers: a dependency changed; a step became wrong; bloat is hurting clarity; an overfit rule caused failures elsewhere.

Append grows coverage. Refine improves precision/quality. Remove prevents drift and bloat. All three are needed — a skill that only ever grows becomes a bloated, contradictory mess; one that only refines never covers new ground.

THE LEARNING LOOP

Learning isn't the edit itself — it's the cycle around it:
1. Act — run the task using the skill.
2. Observe — did it succeed? Where did it stumble, guess, or need help?
3. Reflect — diagnose the gap: missing knowledge (append), wrong/ambiguous knowledge (refine), or stale knowledge (remove).
4. Propose — draft the concrete change (a diff, not a vague intention).
5. Apply — make the edit.
6. Verify — re-run the task / tests / review to confirm the change actually helps and doesn't regress.
7. Persist & version — commit the change with provenance, so a bad "lesson" can be reverted.

Step 6 is what separates learning from mere editing. Without verification you're just accumulating unvalidated opinions.

WHO CARRIES IT OUT — AGENT, USER, OR BOTH?

Agent-only (autonomous self-improvement): The agent detects a gap during a task and edits its own skill. Fast, scales, no human bottleneck. Risks: overfitting to one task, silent degradation, drift, "learning" a wrong lesson, prompt-injection via skill files. Needs guardrails: sandboxing, change logs, eval suites, and ideally a review gate.

User-only (manual authoring): A human writes and maintains the skill. Reliable, high-quality, fully controlled. Costs: laborious, slow feedback loop, doesn't scale, and the human often doesn't see the failure modes the agent hits in practice.

Cooperative / human-in-the-loop (usually best): The agent proposes, the human approves. The agent drafts the specific diff and explains its rationale (citing the failure that motivated it); the user reviews, edits, or rejects. This combines the agent's ground-level observations with the human's judgment and accountability. It's the pattern most production systems converge on: the agent does the labor of noticing and drafting; the human keeps the veto.

A practical rule of thumb: the more consequential the skill and the less verifiable the task, the more the loop should shift from agent-only toward cooperative. Low-stakes, well-tested domains (with strong automated evals) can safely lean autonomous; high-stakes or hard-to-verify domains need a human gate.

Q: What is memory? (General concept. Elaborate from "memory is the record made in past events that changes the future behavior," across four axes: scale (atom to universe), time (microsecond to life of universe), state (physical to mental), and collective scope (personal to national). Not agent memory or any computer/programming/AI thing.)
A:
The fourth axis ("personal → national") is not physical size — it's the breadth of the remembering subject, from a single mind to a whole society. The word is probably "collective" (or social scope / level of aggregation). So the four axes are: what the memory is made of (state), how big the recording system is (physical scale), how long it lasts (time), and who is doing the remembering (collective scope). Four different questions you can ask of any memory.

THE DEFINITION, UNPACKED

Three load-bearing parts:
1. "A record made in past events" — some event leaves a persistent physical (or mental) alteration in a substrate. Something changed and stayed changed. This is the trace.
2. "That changes the future behavior" — the trace must be causally efficacious: it biases how the system responds to later events. This separates memory from mere residue.
3. A reader/effect (implicit) — a trace functions as memory only when something later reads it and is thereby changed. A footprint no one ever meets is a latent record; it becomes memory when it modulates a future response.

Memory is substrate-independent in its logic: past event → persistent alteration → biased future response. The substance can be electron spins, chemical bonds, proteins, synapses, rock, ink, or spacetime — the pattern is identical. Memory is defined not by what it's made of but by what it does: it carries information about the past that is used to shape the future. It is a causal bridge from what happened to what happens next.

Two corollaries:
- Memory is lossy and reconstructive, never playback. Every substrate degrades; every record is partial. Memory is a bias shaped by a degraded trace, not a perfect copy of the past.
- Memory requires the arrow of time. A record can exist only if the process that made it was irreversible — recording costs entropy. No memory in a world with no thermodynamic direction.

The four axes are largely independent: any single memory can be located on all four at once (e.g., national memory of a war = mental + huge physical scale + decades + collective; a cosmic-ray track in a mineral = physical + atomic scale + billions of years + no subject at all).

AXIS 1 — PHYSICAL SCALE: ATOM → UNIVERSE

Subatomic: a system's quantum state is a record of its interactions. An electron's spin, once entangled or measured, retains a correlation with the event that set it; that state constrains the next interaction. Decoherence is the erasure of this memory — the record leaking into the environment. The state is the trace of what happened to it.

Atomic: an atom remembers its history in electron configuration and isotopic identity. Carbon-14 "remembers," in its unstable configuration, when it was formed — exactly how radiocarbon dating reads the past. Hysteresis (state depends on the path taken, not just present conditions) is atomic-scale memory: the present encodes the route.

Molecular: chemical bonds and geometry store synthesis history. Protein folding: a protein's shape records its assembly and environment and dictates what it does next. DNA is the canonical molecular memory — a sequence recording billions of years of evolution that directs future protein synthesis. Epigenetics (methylation) records environmental exposure and later alters gene expression.

Cellular: the immune system — B/T cells that met a pathogen persist and respond faster on re-exposure; past infection rewrites future behavior. CRISPR in bacteria stores fragments of past viral invaders and uses them to cut the same virus later: a heritable, sequence-based memory of past attacks.

Organism/neural: synaptic plasticity biases future signaling. Habituation is memory at the whole-organism level. Muscle memory, immune memory, hormonal set-points all record past states and modulate future response. In humans this branches into episodic (events), semantic (facts), and procedural (skills) memory.

Social/collective: memory escapes the skull — language, writing, law, institutions, tradition, archives are records made by past events that change the future behavior of whole societies. A constitution is collective memory — a trace of past conflict that constrains future governance.

Geological/planetary: rock strata, ice cores, tree rings, sediment are the Earth's memory. Each layer records the conditions of its formation; read in sequence, it reconstructs climate history. A river follows the channel its own history carved.

Astronomical: a star's metallicity records how many prior generations of stars died to seed it — a memory of galactic chemical history. Galaxies preserve the scars of past mergers in their structure. Light itself is memory: every arriving photon is a record of a distant past event.

Cosmic: at the largest scale, the universe is a memory of its own initial conditions. The cosmic microwave background is a fossil of ~380,000 years after the Big Bang; the large-scale distribution of matter encodes primordial quantum fluctuations. Whether information is ultimately preserved (the black-hole information question) is, at bottom, whether the universe has perfect memory.

AXIS 2 — TIME: MICROSECOND → LIFE OF THE UNIVERSE

Microseconds and below: quantum coherence and spin-relaxation times; molecular vibrations. Records erased almost as fast as written — memory and erasure blur together (decoherence).

Milliseconds to seconds: neural spike timing, reverberating circuits, the volatile edge of cognition; a struck bell's ring, a heated wire cooling.

Minutes to hours: short-term biological memory, protein conformational states drifting back to baseline, thermal equilibration — long enough to matter for one episode, no further.

Days to years: long-term memory in organisms, immune memory, annual tree rings, seasonal sediment — the record clearly outlives the event and shapes many future episodes.

Decades to centuries: a human lifespan of memory; cultural and institutional memory; a resolution band of an ice core. The past now reaches across generations of experience.

Millennia to millions of years: geological strata, the fossil record, genetic/evolutionary memory in genomes — records spanning the rise and fall of species.

Billions of years: stellar and galactic memory — isotopic abundances recording epochs of nucleosynthesis, the slow chemical enrichment of the cosmos.

~13.8 billion years: the CMB and large-scale structure: records from the earliest moments that persist today. This is what cosmology is — reading the universe's memory of its birth.

AXIS 3 — STATE: PHYSICAL → MENTAL

This axis asks what kind of thing the record is — from an inert material configuration to a consciously experienced recollection. Its key threshold is where a record becomes represented to a subject.

Physical/inert: rock strata, crystal defects, magnetic domains, isotopic ratios, the CMB. A pure physical configuration with no experience attached. The record simply is; nothing "remembers" it. (It becomes memory only when a reader — a geologist, a detector — is changed by it.)

Chemical/molecular: DNA, protein conformation, epigenetic marks. Still physical, but now functional and heritable — the record actively drives downstream processes (which protein gets built, which gene is expressed).

Biological/functional (non-conscious): immune memory, cellular memory, CRISPR. The system uses its past to change its future without any experience — an organism's body "remembers" a pathogen. Functional memory without a mind.

Neural/non-conscious: habituation, procedural and associative memory in animals. A nervous system encodes past stimuli as altered connection strengths that shape behavior — genuine learning, still without subjective recollection.

Mental/conscious: human episodic and semantic memory. Here the record crosses the threshold: it is not just used but experienced, interpreted, and re-lived. The trace gains intentionality (it is about something), meaning, and subjectivity — there is "something it is like" to remember. Mental memory is reconstructive: each act of recall rebuilds the past from a degraded trace, colored by the present.

Reflective/meta: memory of memory — a self-narrative, a remembered remembering. The remembering subject turns its memory back on itself to construct identity over time. This is where memory becomes the substrate of a self.

Crucial point: the mental is implemented in the physical (neurons) but not exhausted by it. Meaning, aboutness, and experience live at the mental level and cannot be read off the synaptic weights alone. The axis marks where a record becomes a recollection — where the past stops merely constraining behavior and starts being known.

AXIS 4 — COLLECTIVE SCOPE: PERSONAL → NATIONAL

This axis asks who the remembering subject is — from one mind to an entire society. The functional definition is unchanged; what changes is the breadth and distribution of the rememberer.

Personal: an individual's episodic and semantic memory. The subject is one mind; the store is one brain. (Axis 3's "mental" state at its smallest scope.)

Interpersonal/shared: a couple's shared memories, family lore, a group's inside references. Memory distributed across a few minds and kept coherent through conversation and re-telling.

Community: oral tradition, local custom, communal ritual. The record lives in repeated practice and storytelling rather than any single head — it survives the death of individuals because it is re-enacted.

Institutional: corporate archives, legal records, scientific literature, professional norms. Memory externalized into artifacts and procedures so that the institution "remembers" beyond the tenure of any member.

National: national archives, monuments, museums, founding myths, official histories, commemorations. A nation remembers through curated artifacts and shared narrative, and that memory changes the nation's future behavior — its laws, foreign policy, and identity. Note the selective, constructed character: nations curate memory and sometimes deliberately forget (erased records, suppressed histories). Collective memory is not the sum of individual memories; it is a separate, edited, transmitted artifact.

Civilizational/global: written language, the accumulated scientific record, the internet. Memory at the widest scope — a species-scale store that outlives every individual and every nation.

Key insights on this axis:
- Collective memory is not just aggregated individual memory. It lives in external artifacts (books, monuments, databases) and is transmitted by communication and ritual, not by genes or synapses.
- It is selective and constructed — societies choose what to keep and what to forget, and the choice serves present needs (identity, legitimacy, cohesion).
- It obeys the same law: the past is retained insofar as it changes future behavior — a national memory endures because it continues to shape policy, identity, and action. When it stops doing so, it fades into inert history.

SYNTHESIS — HOW THE FOUR AXES INTERLOCK

- What / How big / How long / Who — state, physical scale, time, and collective scope are four independent questions. A single memory can be pinpointed on all four at once.
- Physical scale and time are coupled by stability: a record persists only as long as its substrate is stable relative to the event rate. Fast, fragile substrates (quantum states, neural voltages) hold short memories; slow, rigid substrates (rock, genomes, spacetime) hold long ones. To remember long, write into something that barely changes; to remember recent detail, use something volatile. Every memory system trades fidelity against durability.
- State and collective scope are coupled by representation: a purely physical record needs no subject, but the moment memory becomes mental it requires a mind — and the moment it becomes collective it requires many minds plus external artifacts. The "mental" threshold (Axis 3) is where a subject first appears; the "collective" axis (Axis 4) is where subjects multiply and externalize.

Strip away the substrate and the same skeleton appears at every rung, every timescale, every state, and every scope:
1. A past event alters a substrate (the trace).
2. The alteration persists (stability relative to event rate).
3. The persisted trace biases future behavior (causal efficacy).
4. The trace is lossy (degradation, reconstruction, not playback).
5. The trace exists only because time has an arrow (irreversibility, entropy cost).

That is what memory is, in the most general sense: a system whose present state carries usable information about its past, such that this information shapes its future. The footprint, the fossil, the genome, the synapse, the strata, the national archive, and the microwave background are all the same idea wearing different matter — the past refusing to fully let go, and thereby steering what comes next.

Q: From the previous general view of memory, what is the "memory" of an agentic system — from the LLM, to the agent loop, to the harness system, to the running environment, to every work/interaction/record the agent did, and to the user themselves? How does this memory shape the agent and its capability and performance over time? As a user, how do you proactively shape the agent and the environment to benefit the agentic system?
A:
THE CORE CLAIM

An agentic system is a layered memory hierarchy — and the human is one of its layers. It is exactly the four-axis picture from the last answer, wearing silicon and flesh. The general skeleton (past event → persistent alteration → biased future response) holds at every layer. What differs between layers is the same four questions: what the memory is made of (state), how big the store is (scale), how long it lasts (time), and who the rememberer is (scope).

The single most useful reframe: an agent is not a model — it's a model + a memory hierarchy + a human curator. Most of the capability lives in the memory, not the weights; and most of the memory — including the human's own — is editable. The human is not outside the system looking in; the human is a memory layer that also edits all the others.

Here is the hierarchy, bottom-up.

LAYER 1 — THE LLM WEIGHTS: GENETIC MEMORY

What it is: the frozen parameters produced by training. A compressed, lossy record of a vast corpus of past events (text, code, human feedback), where "past events" are training examples and "future behavior" is token prediction.

Axis placement: State = physical (numeric, inert until run); Scale = huge but fixed; Time = longest (fixed for the model's life — months to years, the "life of the universe" of this system); Scope = collective/civilizational (it is the sediment of all of humanity's writing, not any one user's).

Role: it sets the ceiling — the base knowledge, priors, and reasoning capacity. This is the analogue of DNA: it defines the potential of the organism and barely changes within its lifetime (short of fine-tuning, which is "mutation").

Key property: slow, expensive, and hard to edit — so you almost never shape this layer directly as a user. It is the environment's "given."

LAYER 2 — THE CONTEXT WINDOW: WORKING MEMORY

What it is: everything currently in front of the model — the system prompt, the conversation so far, retrieved documents, tool outputs, the current file contents. This is the model's active mental state.

Axis placement: State = mental (this is the layer that is "represented to the subject" — the model reasons over it); Scale = small (a bounded window); Time = shortest (volatile — dies with the session, like a microsecond-to-hours substrate); Scope = personal (one conversation).

Role: it determines the working set — what the agent can hold "in mind" for this task. This is the layer where reasoning actually happens. It is the RAM of the system.

Key properties:
- Volatile — forget everything when the session ends (unless persisted to a lower layer).
- Bounded — too little and complex tasks fall apart; too much irrelevant material and you get context rot / distraction (signal drowned by noise). Quality of context matters far more than quantity.
- The bottleneck — most within-task failures are context failures: the right information wasn't present, or was present but buried.

LAYER 3 — THE AGENT LOOP / SCRATCHPAD: PROCEDURAL SHORT-TERM MEMORY

What it is: the agent's own running plan, notes, intermediate results, and reasoning trace within a task — the "thinking out loud," the to-do list it maintains, the results of each tool call it carries forward.

Axis placement: State = mental/procedural; Scale = small; Time = minutes-to-hours (the task's duration); Scope = personal.

Role: it is procedural working memory — it lets the agent decompose, track progress, and avoid re-deriving. It's the analogue of a human keeping a scratchpad while solving a problem.

Key property: this is where self-correction lives. An agent that writes down what it tried and what failed can avoid repeating mistakes within the task. Poor scratchpad discipline = loops and repeated errors.

LAYER 4 — THE HARNESS SYSTEM: EXTERNALIZED, EDITABLE MEMORY — THE HIGHEST-LEVERAGE LAYER

What it is: everything that scaffolds the model but lives outside the weights and outside the ephemeral context:
- the system prompt / instructions (the agent's standing orders and persona),
- the tools and skills (SKILL.md files, scripts, reference docs — from Q1/Q2),
- the persistent memory stores (records databases, vector stores, notes files),
- the config (which tools are enabled, how they connect).

Axis placement: State = physical artifact (files, DBs) that becomes mental when loaded into context; Scale = medium (a repo of skills/records); Time = long (persists across sessions, days-to-years); Scope = institutional (shared across users, not just one session).

Role: this is procedural competence and accumulated learning. It is precisely the "learning substrate" from Q2 — the thing you refine / append / remove. It is where an agent stops being a stateless tool and becomes a system that improves at recurring tasks.

Why it's the highest-leverage layer: for a fixed LLM, nearly all durable capability gains come from here, not from the weights. You cannot retrain the model per-user; you can write a skill, curate a memory store, or fix a config. This layer is the difference between "a clever chatbot" and "a specialist that gets better every week." It is also the layer where drift and bloat accumulate — stale skills and contradictory records silently degrade performance.

LAYER 5 — THE RUNNING ENVIRONMENT: WORLD MEMORY

What it is: the file system, the repos, the databases, the OS state, the artifacts the agent produced — files it wrote, git history, logs, test results, build outputs. The agent's traces in the world.

Axis placement: State = physical; Scale = large (a whole workspace); Time = long (persists, versioned); Scope = institutional/shared.

Role: this is the affordances and feedback layer. It determines what the agent can do and what it can observe about what it did. A well-structured environment (clear files, automated tests, version control, logs) is itself a memory that teaches the agent — the test output is a record that immediately biases the next action. A messy environment starves the agent of feedback.

Key insight: the environment is readable memory. Git history is collective memory (Axis 4) of what changed and why. Test suites are predictive memory — records of expected behavior that catch drift. Logs are episodic memory of what happened. A good environment is a self-correcting memory system — it tells the agent when it's wrong.

LAYER 6 — THE RECORDS / TRANSCRIPTS / TRACES: EPISODIC MEMORY OF THE SYSTEM

What it is: the logs, conversation transcripts, tool-call traces, evaluation results — the raw history of every interaction the agent did.

Axis placement: State = physical (stored records) but about mental events; Scale = large and growing; Time = long (an archive); Scope = institutional/civilizational (the accumulated record).

Role: this is the episodic memory from which learning is extracted. You cannot run the Q2 learning loop (observe → reflect → refine/append/remove) without it. It is the "record of past events" in the most literal sense — and it changes future behavior only when something reads it and acts (an eval that reveals a weakness, a reviewer who spots a repeated failure, a reflection step that updates a skill).

Key property: on its own it is inert residue. It becomes memory (in the strict definition) only when it feeds back — into a skill edit, a config change, an environment fix. An archive nobody reads is a footprint nobody meets.

LAYER 7 — THE HUMAN: THE CURATOR'S MEMORY — EXPERIENCE AND SKILL — THE LAYER THAT EDITS THE OTHERS

This is the keystone layer, and it is genuinely part of the agent's memory — not metaphorically, but functionally, because the user's stored knowledge, experience, and skill bias the system's future behavior at every other layer.

What it is: the human carries several distinct kinds of memory:
- Declarative memory of the system — knowing what the agent is good at, where it fails, which tasks it can be trusted with. A model of the model.
- Episodic memory of past sessions — remembering that last time the agent looped on X, that Y approach worked, that Z config broke retrieval. The human's own episodic trace of the agent.
- Procedural memory / skill — the craft: prompting, writing good skills (clear descriptions, good scripts), structuring an environment, knowing when to trust vs. verify. This is the user's skill in exactly the Q1/Q2 sense — and it is the bottleneck on how good the harness ever gets.
- Intent / values memory — the goals, constraints, taste, and standards the user holds, externalized into system prompts, configs, and acceptance criteria.

Axis placement: State = mental (the richest, most interpretive kind); Scale = one mind (amplified by team — see collective below); Time = long (a career of experience, decades); Scope = personal→institutional (the user bridges individual and team).

Role — three jobs at once:
1. A memory store — the human holds context the system doesn't (why a skill exists, what "done" means, the unwritten constraints). This is working memory for the whole system, outliving any session.
2. The verifier — the Q2 loop's "verify" step. The agent proposes, but the human's judgment is what makes a change stick or get reverted. Without the human's memory of past failures, the learning loop has no ground truth.
3. The gardener of every other layer — the user writes the skills (Layer 4), designs the environment (Layer 5), curates the context (Layer 2), reads the records (Layer 6), and chooses the model (Layer 1). The human is the only layer with write-access to all the others. The user's own skill and experience are therefore the master variable — the ceiling on how well the whole memory hierarchy is built.

Key property: the human layer is lossy, tacit, and bottlenecked by attention — you forget which skill is stale, you don't scale to many agents, your craft is hard to transfer. That is exactly why the lower layers exist: to externalize the human's memory and skill so they persist, scale, and don't die with one person's attention.

And the collective human layer: on the "personal → national" axis, one user is a point; a team sharing skills, conventions, and review practices is institutional memory; an organization's harness, standards, and shared record is national-scale memory. This is how individual user-skill becomes durable organizational capability — the same way personal memory becomes a constitution or an archive (Q3, Axis 4). A well-run team's skill library is the institutional memory of "how we do things here," transmitted by practice and review rather than living in any one head.

HOW THIS MEMORY SHAPES CAPABILITY AND PERFORMANCE OVER TIME

The layers are not a flat list — they are a stack with different time constants, and performance is the product of what each supplies:
- Weights set the ceiling (what's possible at all).
- Context sets the working set (what's possible right now).
- Harness sets procedural competence (how reliably recurring tasks get done).
- Environment sets feedback quality (how fast errors get caught).
- Records set the learning rate (how fast the system improves).
- The human sets the whole trajectory (how well all of the above get built and maintained).

The crucial dynamic is compounding vs. drift:
- Compounding (positive loop): good harness + clean environment + a skilled curator → each task slightly easier than the last → skills sharpen, records accumulate into reusable knowledge, the human learns the system's quirks → the agent gets better every week without the weights changing. This is the payoff of treating memory as editable.
- Drift (negative loop): stale skills, contradictory records, a messy environment, an inattentive curator → the agent silently gets worse, confidently repeating outdated behavior → trust erodes → the human stops investing → decay. Drift is slow and invisible because nothing crashes; it just degrades.

And the stability/time coupling from Q3 applies exactly: volatile layers (context, scratchpad) hold rich recent detail but forget fast; durable layers (weights, skills, environment, records) hold coarse but long-lived records. Every task trades fidelity against durability — solve it in the scratchpad (volatile, detailed) or commit it to a skill (durable, coarse)? The art of building an agentic system is choosing the right layer and time constant for each piece of knowledge.

The arrow-of-time / entropy point also holds: memory decays unless actively maintained. Skills rot, records go stale, environments drift. Maintenance is not optional — it is the price of the memory persisting, exactly as recording costs entropy.

FOUR-AXIS MAP OF THE HIERARCHY

Layer | State | Physical scale | Time constant | Collective scope
LLM weights | physical | huge | longest (years) | civilizational
Context window | mental | small | shortest (session) | personal
Agent scratchpad | mental | small | task (min–hrs) | personal
Harness (skills/DB/config) | artifact→mental | medium | long (days–years) | institutional
Running environment | physical | large | long (versioned) | institutional
Records/transcripts | physical-of-mental | large | long (archive) | institutional
Human (user/team) | mental | one mind (amplified by team) | decades | personal→institutional

AS A USER: HOW TO PROACTIVELY SHAPE THE SYSTEM

The human is the only layer with write-access to all the others, so your leverage is enormous — and it is mostly indirect: you shape the system by shaping its memory, and by shaping yourself as its curator.

Shape yourself (Layer 7 — the master variable):
1. Build a mental model of the model — track what it's good/bad at, where it hallucinates, what it needs supervision on. Your experience is system memory; write it down so it survives your attention.
2. Develop the craft — learn to write crisp skill descriptions, decompose tasks, design good tool/environment interfaces. Your skill caps how good the harness can ever be.
3. Externalize your tacit knowledge — move what's in your head (constraints, "done" definitions, gotchas) into the harness (prompts, skills, configs) so it persists and scales beyond you.

Shape the context (Layer 2):
4. Curate, don't flood — feed relevant, well-organized material; scope tasks; keep noise out. Quality of context beats quantity; irrelevant content causes context rot.
5. Make the working set visible — for complex tasks, ask the agent to externalize its plan/notes so its own scratchpad (Layer 3) is inspectable and correctable.

Shape the harness (Layer 4 — highest leverage):
6. Invest in skills — write clear descriptions (routing), ship scripts for mechanical steps, keep bodies lean, push long references to references/.
7. Run the Q2 loop deliberately — when the agent fails, observe → reflect → refine/append/remove the skill; verify the change; version it. This is where compounding happens.
8. Curate persistent memory — keep the records store accurate; prune stale/contradictory entries; treat it as a maintained asset, not a dump.

Shape the environment (Layer 5):
9. Make it self-correcting — automated tests, linters, clear file structure, version control, logs. A failing test is memory that teaches the agent instantly; it's the cheapest reliability you can buy.
10. Provide legible affordances — clear tools and interfaces so the agent can act and observe the results of its actions.

Shape the records & feedback (Layer 6):
11. Keep the transcript/log/eval trail — you can't learn without episodic memory; run evals so weaknesses surface as records, not surprises.
12. Close the loop — ensure records actually feed back into skill/config/environment edits. A record nobody reads is dead weight.

Guard against drift (all layers):
13. Version and audit — version-control skills and configs; periodically review for staleness and bloat; revert bad "learning."
14. Respect the memory definition — if a record doesn't change future behavior, it's not memory, it's clutter. Keep only what shapes outcomes.
15. Match memory to time constant — one-off detail → volatile context; recurring knowledge → durable skill; institutional convention → shared harness. Put each piece of knowledge on the right layer.

The one-line synthesis: You are not prompting an agent; you are gardening a memory system — of which you are the most important and most editable layer. Tend the layers with the longest time constant and the widest scope (skills, environment, records, your own skill), because that is where compounding lives; and prune relentlessly, because memory decays unless maintained.
